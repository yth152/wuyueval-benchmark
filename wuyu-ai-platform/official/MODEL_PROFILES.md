# 多模型配置

问答框的“模型”菜单可选择 `wuyu-shensi` 或“在线 Qwen 27B”。每轮提问保存模型标识、显示名称和当时的接口参数；历史对话恢复最近一轮的模型选择。旧记录默认属于训练模型。

管理员在“模型配置”中管理默认模型，并通过“添加模型”增加最多 32 个其他模型。各模型独立配置接口地址、接口 model 名称、密钥、上下文容量与接口适配；可停用或移除其他模型。密钥留空保持原值，页面只返回是否配置，不返回密钥。

- 默认训练模型：显示名 `wuyu-shensi`，接口 model 为 `qwen3.8-27b-tmidtrain`，地址 `http://103.139.212.177:8444/v1`。
- 之前的在线模型：显示名“在线 Qwen 27B”，接口 model 为 `qwen3.8-27b`，地址 `https://www.dmxapi.cn/v1`，模型标识 `baseline`。
- 思考参数可选 `chat_template_kwargs.enable_thinking`、顶层 `enable_thinking`、两者同时发送，或标准兼容接口（不发送思考参数）。已有在线 Qwen 模型沿用两者同时发送；新模型默认不发送。
- “图片理解”控制 `text` 后附 `image_url` 的标准多模态消息；纯文本模型会明确拒绝图片，文档仍可解析为文本。当前支持图片输入和语音转文字，不等于支持任意音视频原生输入。
- “原生工具调用”控制是否允许用户启用联网工具。模型可按需选择管理员已启用的网页、学术和自定义工具。
- “测试已保存接口”发起一条最多 128 tokens 的文本请求。测试成功不代表图片或工具能力已经验证；这些能力需要实际部署和专门任务支持。

其他模型可独立设置系统提示词、输出上限和温度；留空沿用默认值。工具配置与账号额度由平台统一管理。当前正式实例默认常规输出上限为 16,384 tokens；多人排队时仍按既有繁忙输出上限 4,096 与该模型输出上限的较小值执行。现有两个模型都采用 32,768 的应用侧上下文预算；这是本地配置，并非在线服务实际容量的探测结果。配置时校验每个启用模型都能容纳输出预留，并在排队时按所选模型的上下文容量预留资源。

额外模型密钥以 Fernet 加密保存在后端数据库。`baseline` 可用环境变量 `WUYU_MODEL_BASELINE_API_KEY` 覆盖；其他模型规则为 `WUYU_MODEL_<大写模型标识>_API_KEY`。默认模型仍使用 `WUYU_MODEL_API_KEY`。移除模型时保留加密密钥，供此前排队的任务使用；新请求无法选中停用或移除的模型。

上线前应等待现有任务完成再更换接口密钥。页面退出、切换对话不取消后台生成。所有模型共享现有按用户公平排队和预算控制，真实并发容量仍需在模型服务结束大量测试后验证。

验证：`python -m unittest -q test_models.ModelTests` 覆盖路由、上下文预留、旧记录兼容、密钥隔离、配置校验、权限及未配置模型不占用额度。隔离 UI 服务 `qa_server.py` 使用虚拟模型回复，不向真实服务发送测试页面中的内容。
