# 无隅 AI 正式版

新版入口为 **http://127.0.0.1:8920/**。问答功能沿用 `model-chat` 的原生模型工具调用、文件解析、多模态请求和引用侧栏；登录页沿用原平台设计，用户数据、权限和生成任务改由服务器保存。旧版 8910 及原联合模型平台独立保留。

## 本机启动与首次管理

1. 双击 `启动正式版.cmd`。也可运行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`。
2. 普通用户点击“立即注册”，填写邮箱、密码（8–128 个字符）、姓名、机构和身份，注册成功后直接进入问答。以后只需邮箱和密码登录，不需要验证码或 SMTP；邮箱作为账号标识，不校验邮箱所有权。
3. 系统管理员由服务器管理人员在 `official` 目录执行 `..\.venv\Scripts\python.exe manage.py create-admin` 创建，按终端提示填写邮箱、姓名、机构和密码；密码输入不回显，也不作为命令行参数传递。随后在同一个登录页使用邮箱和密码登录。
4. 右上角“系统管理”提供模型配置、工具管理、语音服务、对话记忆、容量额度、账号设置、用户管理和 JSON 数据导出。普通注册始终为普通用户，首个注册用户不会自动取得管理员权限。
5. 忘记密码，或升级前已存在尚无密码的账号，由服务器管理人员执行 `..\.venv\Scripts\python.exe manage.py set-password --email 用户邮箱`，交互设置新密码。原账号和历史数据保留，原登录会话失效；迁移不会提供可被别人用同邮箱重新注册的入口。

旧验证码和网页初始化接口已移除，旧 `bootstrap.token` 不再参与认证。升级前数据库备份保存在 `runtime/backups`。密码以独立随机盐的 scrypt 散列存储，不可从数据库还原明文，也不会通过用户资料或管理接口返回。

停止本版：运行 `stop.ps1`。此脚本核对 PID 和完整应用路径，只停止本版进程。停止后，正在生成的任务将在下次启动时标记为中断，保留已收到的内容；尚未开始的排队任务在启动后继续。

现有模型和检索密钥已导入本版加密存储。页面显示名称为 `wuyu-shensi`；接口的 `model` 参数与显示名分别配置。2026-10-08 按提供的新连接更新为 `http://103.139.212.177:8444/v1`，接口模型为 `qwen3.8-27b-tmidtrain`。后续可由管理员更新，保存后用于新提交的任务。不要把服务器上使用的 `127.0.0.1` 误填为 Windows 本机地址。

## 使用与数据

- 左下角齿轮或个人头像打开“系统设置”：浅色/深色/跟随系统主题、18/20/22px 问答字号、Enter 或 Ctrl/⌘+Enter 发送；个人偏好按账号存入数据库。默认浅色，问答页和管理页共用主题。
- “账号管理”可修改姓名、机构和身份；登录邮箱与账号权限不能在这里修改。“数据管理”显示个人对话、附件和当日用量，支持只导出当前账号的 JSON 数据。管理员的全用户导出入口保留在系统管理中。
- 问答框的“模型”菜单可切换 `wuyu-shensi` 与“在线 Qwen 27B”。管理员可添加、停用和移除其他模型；各模型使用独立接口与密钥。配置规则见 [多模型配置](MODEL_PROFILES.md)。当前正式实例常规输出上限为 16K，繁忙上限仍为 4K。
- 注册时填写姓名、所在机构、身份，登录仅需邮箱和密码；每个账号仅可访问自己的对话、附件、任务和导出文件。
- 生成时可新建或切换对话、刷新、关闭网页或退出登录；任务仍由服务器执行，重新登录后在历史对话查看。点击“停止生成”才主动取消。
- 输入框的“智能记忆”可切换智能检索、最近对话或仅当前问题，并控制自动压缩/手动整理。完整档案在数据库中保留，每轮按预算重新构造请求；方案、默认值和限制见 [多轮记忆与数据导出](MEMORY_AND_EXPORT.md)。
- 管理员在“系统管理 → 数据导出”可选择用户或导出全部用户 JSON，支持附带文档解析文本与图片。普通用户仍只访问自己的数据；密码和服务密钥不导出。
- 深度思考展示模型接口实际返回的内容。联网开关打开后，由模型自行决定是否调用网页或学术搜索，中英文分开检索，每次最多 10 个来源，学术默认近十年优先。引用显示编号，并在右侧按网页/文献分组。
- 每轮最多 5 个附件，文档单个 20 MB、图片单个 10 MB、合计 50 MB。支持 DOCX、PPTX、XLSX、XLS、PDF、文本及常见图片；旧 DOC/PPT 先另存为新格式。支持粘贴图片、拖放文件、长文本转附件。
- 当前解析每份文档最多选取 12,000 字符、每轮文档最多 24,000 字符；被截断时明确提示。扫描 PDF 没有自动 OCR，复杂图表不等于全文理解。
- 每人附件空间可配置，底层附件目录还有 500 MB / 约 2,000 个存储文件保护上限。移除对话只隐藏历史，不删除额度账目和附件。上线前按存储规模规划清理与备份。
- 生成数据位于 `runtime/platform.sqlite3`；密钥以 Fernet 加密，解密文件为 `runtime/vault.key`。只备份数据库不能恢复密钥，需把数据库、密钥文件、uploads 一并保护和备份。浏览器不持有模型和检索密钥。

## 工具和语音扩展（2026-10-08）

登录与注册页现在使用 WebGL 实时变形流光，提供暂停按钮；减少动态效果或设备不支持 WebGL 时使用静态背景。页面隐藏时停止推进动画时间。

“工具管理”保留网页与学术搜索，允许增加最多 22 个自定义 **HTTP/JSON 查询工具**。可配置名称、使用说明、参数 JSON Schema、GET/POST、Bearer 或自定义请求头密钥、超时、固定参数与响应映射。密钥加密保存，留空保持不变。支持停用、修改、移除及保存后单独测试；测试会实际调用接口。

示例：工具输入 `{"query":"固废资源化"}`，接口返回 `{"data":{"answer":"..."},"sources":[{"title":"资料标题","url":"https://example.com/article","snippet":"摘要","date":"2026-01-01"}]}`。结果路径设置为 `data`、来源数组路径为 `sources` 即可；嵌套路径用点号，如 `data.articles`。自定义接口字段可映射到标题、网址、摘要、日期、作者。最多取 10 条来源，进入现有编号引用与右侧网页/文献列表；没有来源的数据也会进入工具记录，但不会伪造引用。

用户打开“联网工具”后，后台将可用工具 Schema 提供给模型，由原生 `tool_calls` 决定调用。不开启时不会提供或执行工具。工具合计最多 8 个请求、4 轮；一次内置双语搜索占 2 个请求。自定义响应上限 1 MB，送入模型的结果摘要最多 6,000 字符；错误、截断和缓存复用均有标记。只开放查询接口，写入、发信、付款、删除等有副作用的工具不在此入口支持范围内。当前不是远程 MCP 客户端；MCP 服务需要封装为 HTTP 查询接口后接入。

模型和工具在下次任务生效，其他已登录页面每 30 秒或重新聚焦时更新可选配置；运行中任务不被强制切换。工具被停用、删除或其配置发生变更后，旧任务不会继续调用过期工具。

语音按钮位于问答输入框右下方。使用讯飞实时识别，录音后文字填入输入框，由用户核对后发送；取消、切换对话、离开页面会关闭麦克风。默认每段最多 120 秒、全平台同时 2 路、每人滚动 24 小时最多 60 次，可由“语音服务”调整。沿用了此前专家审核系统的服务配置，三项凭据保存在本平台加密存储中，不进入浏览器。只保存调用次数、时长和状态，原始音频不落盘；调用记录包含在对应用户的 JSON 导出中。

云端录音必须使用 HTTPS（本机 localhost/127.0.0.1 可用），Nginx 模板已增加 `/api/voice/stream` 的 WebSocket 转发。搬迁时同时备份数据库、vault.key 与附件目录，不复制任何测试账号数据。

验证：原有 53 项回归及新增模型/工具/语音边界测试通过；原生工具选择、参数验证、来源引用、模型独立预算、语音鉴权与断连清理使用隔离数据测试。另通过真实讯飞服务转写了 5.69 秒合成中文测试音频，返回预期文本。实际用户麦克风权限需用户在浏览器首次录音时授予；未做真实模型并发压测。

## 多用户调度

这些是已实现的应用侧控制，尚未通过真实模型并发压测，不能据此推算 GPU 吞吐：

| 项目 | 默认值 | 行为 |
| --- | --- | --- |
| 全平台同时生成 | 2 | 达到后排队 |
| 每人同时生成 | 1 | 同一账号不能占满所有生成位置 |
| 每人待处理任务 | 3 | 包含生成中与排队中 |
| 平台排队上限 | 64 | 超出时明确告知稍后提交 |
| 排队规则 | 按用户轮流 | 每个用户内部按提交顺序，当前对话串行 |
| 同时在途容量 | 65,536 tokens | 每个任务按所选模型的完整上下文容量预留，当前两模型均为 32,768 |
| 单任务累计预算 | 131,072 tokens | 累加模型各轮输入和输出，不只计算最终回答 |
| 每人每日额度 | 2,000,000 tokens / 100 次 | 北京时间切日；提交先预留，完成后结算，避免并发超卖 |
| 常规 / 繁忙输出 | 8,192 / 4,096 tokens | 多用户排队时，对新开始的任务使用繁忙上限并提示；不截断已开始的生成 |
| 任务超时 | 900 秒 | 保存已生成内容并释放位置 |

有完整接口用量时按上报值结算并返还未使用预留；取消、断连、缺失用量时采用保守估算并明确标记。上下文估算和应用侧容量预留不是 GPU 显存测量，也不保证各用户相同 token/s。模型测试完成后再根据显存、上下文、首字延迟、吞吐调整参数。旧 8910 或其他客户端的直连请求不经过本版队列；要统一限制所有请求，需让它们都经过同一入口或在模型网关统一调度。

## 云服务器部署模板

目前未执行云端部署。准备好域名、HTTPS、模型可访问地址后：

1. 保留目录结构：项目根目录的 `requirements.txt`、`package.json`、`package-lock.json`，以及 `official/` 与 `model-chat/`。运行依赖不包含旧前端，但复用 `model-chat` 的 Python 模块及解析工作进程。
2. 使用 Python 3.11+ 建立项目根目录 `.venv`，安装 `official/requirements.txt`。在项目根运行 `npm ci`，再进入 official 使用 `node ../node_modules/vite/bin/vite.js build --config vite.config.mjs`。
3. 建立独立系统账号 `wuyu`、数据目录 `/var/lib/wuyu`，仅该账号可读写。复制 `deploy/platform.env.example` 到 `/etc/wuyu/platform.env`，替换真实域名并限制文件读取权限。模型和检索密钥可在管理页配置，也支持示例列出的环境变量；环境变量优先于管理页保存值。
4. 按 `deploy/wuyu.service` 使用 systemd 启动。**必须单进程、单 worker**：进程锁会拒绝同一数据目录的第二个调度器。一个 worker 仍可异步处理多个用户的生成任务。
5. 使用 `deploy/nginx.conf.example` 配置 TLS 反向代理。保留关闭流式缓冲、请求体上限和较长读取超时；服务自身只监听 127.0.0.1:8920。`WUYU_ALLOWED_ORIGINS` 要精确匹配外部 HTTPS 域名，设置 `WUYU_SECURE_COOKIE=1`。
6. 以服务账号、同一个数据目录环境运行 `python manage.py create-admin` 创建管理员，验证邮箱密码注册和登录。上线后定期备份并监控任务失败、排队长度、磁盘使用。

当前持久化适合单服务实例，未实现跨机器 Redis 队列、PostgreSQL、多副本调度或重启后续接模型 KV cache。浏览器退出不影响任务；服务器进程重启会中断正在生成的任务并提示重新提问。
