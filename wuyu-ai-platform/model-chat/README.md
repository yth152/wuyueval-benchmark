# 无隅AI平台 · 模型测试版

一个可在本机打开的模型聊天界面，直接连接团队训练模型和已有的在线 Qwen 基线。

## 使用

1. 双击本目录的 **启动问答.cmd**，或打开已启动的 <http://127.0.0.1:8910>。
2. 默认使用 **wuyu-shensi**。输入问题，按 Enter 发送；Shift + Enter 换行。
3. 默认开启思考。回答上方的“模型返回的思考内容”可以展开或折叠。
4. 输入框下方的 **联网搜索** 默认关闭。开启后，模型可自主调用秘塔网页搜索或学术搜索，也可以判断无需搜索而直接回答。
5. 回答末尾的“网页”和“文献”胶囊按钮分别展示检索来源数量，点击后在右侧打开详情；可切换类别、筛选“仅看已引用”。正文数字引用会定位对应卡片，卡片标题打开原网页；Ctrl/Cmd 点击正文引用也可直接打开原网页。检索总量与正文实际引用量分别显示，不将所有搜索结果标为已引用。展开“工具调用记录”可查看搜索词和结果。
6. 输入框右下角的回形针支持文件选择；也可拖入文件或直接粘贴剪贴板图片；超过 4,000 字符的粘贴文本自动转成文本附件。每轮最多 5 个文件，文档单个 20 MB、图片单个 10 MB、合计 50 MB。
7. 输入框底部的 **模型** 按钮用于切换模型；左侧图标栏可以打开历史对话、导出当前对话和打开设置。导出包含正文、思考、工具记录和引用来源。切换到其他模型会新建对话。
8. 双击 **停止问答.cmd** 可关闭本机服务；浏览器中的对话历史仍会保留。

浏览器关闭不会关闭服务。电脑重启后需重新运行启动脚本。服务仅监听本机 `127.0.0.1:8910`，没有对外网开放。

导出的 Markdown 文件保存在本目录的 `output/exports` 下，页面会显示完整保存路径，也可点击“下载副本”。

## 已实现

- 与正式平台一致的白色画布、蓝紫控件、图标侧栏、品牌标识和首页布局；保留本测试版的直连模型及原生 Agent 流程。历史记录沿用原来的浏览器存储，并支持标题搜索。
- 多轮对话、中文流式输出、Markdown 排版、表格和代码块。
- 显示模型接口返回的 `reasoning` 或 `reasoning_content`；兼容开头的显式 `<think>…</think>`。
- 思考开关；没有独立思考内容时明确提示，不生成替代内容。
- 停止生成，显示超时、错误、截断和未完成状态。
- 仅将完整问答带入后续上下文；思考内容不回传。默认最近 10 轮，可调整到 0 / 3 / 5 / 10 / 20 轮。
- 浏览器保存最多 30 个对话；可删除、复制回答、导出含思考内容和参数的 Markdown 记录。
- 温度、最大输出长度、系统提示词设置。默认温度 0.2、最大输出 8,192 tokens。
- 页面显示产品名称 wuyu-shensi、耗时、首段内容到达时间、返回的 token 用量（服务不提供时不估造）。实际接口模型别名保留在诊断数据中。
- 原生 Agent 工具调用：`tools` + `tool_choice: auto` → 模型返回 `tool_calls` → 执行对应秘塔工具 → 以 `role: tool` 返回结果 → 模型继续决定或回答。
- 网页与学术搜索各自独立，每次固定向秘塔请求 `size: "10"`。实际少于10条、重复链接、空结果或失败时如实显示，不补造来源。
- 正文引用映射真实检索结果，来源侧栏区分检索结果与正文已引用；未知编号会提示未匹配，不伪装成已核验来源。

## 模型与凭据

| 选项 | 请求模型 | 模型接口 |
|---|---|---|
| wuyu-shensi | `qwen3.8-27b-tmidtrain`（当前服务别名） | 用户提供的团队服务 |
| 在线 Qwen 基线 | `qwen3.8-27b` | 已配置的 DMXAPI；实际响应可能显示 `qwen3.8-27b-fp8` |

2026-10-06 实测：团队服务尚未注册 `wuyu-shensi` 请求别名，直接请求会返回 404。页面、模型选择和系统身份已经统一为 wuyu-shensi；后端暂保留可用的服务别名。服务端注册新名称后，可更新 `credentials.py` 的 team.model，不能只改请求名称导致连接失效。

团队密钥保存在 `runtime/team.dpapi`，由 Windows DPAPI 加密，只能由保存它的 Windows 用户解密。在线基线默认只读已有 `solid-waste-distiller` 平台的指定供应商配置。也可设置后端环境变量 `TEAM_API_KEY` / `BASELINE_API_KEY`，其优先级更高。

秘塔密钥优先读取 `METASO_API_KEY`，其次为本目录 `runtime/metaso.dpapi`，最后只读上级平台 `runtime/platform.sqlite3` 的 `metaso_secret`，使用该平台已有 `vault.key` 解密。前端和模型均无法读取秘塔密钥。

密钥不会进入网页、导出记录或版本管理。除用户明确上传的附件外，服务不自动记录问题与回答；会话文本存于当前浏览器的 localStorage，点击导出时才会另存本机文件。不同浏览器及 `localhost` / `127.0.0.1` 地址之间的历史记录不共享。更换电脑前请导出需要保留的记录。

网页只向本机后端请求；后端把问题和所需历史发往所选模型服务。开启联网后，只有模型返回完整、有效的原生工具调用，后端才把模型生成的搜索词发给秘塔，再把检索摘要返回模型。原平台的问题改写、知识库和审校链路未接入此入口。

## 搜索工具与引用规则

| 工具 | 秘塔 scope | 使用场景 | 固定请求数量 |
|---|---|---|---|
| `web_search` | `webpage` | 政府公告、企业公开资料、时效性事实 | 10 |
| `scholar_search` | `scholar` | 学术论文、研究方法、文献证据 | 10 |

两个工具均要求模型先提交 `query_zh` 和 `query_en`：将问题拆为中文关键词和对应的专业英文关键词，后台分别并发检索。学术工具可选 `period`，默认 `recent_10_years`；明确研究历史或经典文献时可用 `all`。工具名称和两种语言的搜索词由模型选择。关闭开关时不发送工具定义，不执行搜索。开启后不强制预检索、不用关键词规则替模型选工具，也不把普通回答里的 JSON 或 `<tool_call>` 文本当作真实调用。

模型可在一次回答中先后搜索、同时提出两种搜索请求，再根据结果补充检索。当前每次提问最多执行8个语言检索请求（4组中英文）、4轮工具交互，随后通过 `tool_choice: none` 要求模型用已有证据收尾。相同工具、查询和时间范围的重复调用会复用该次提问内的结果。

### 多次搜索与上下文容量

团队部署服务当前返回的上下文上限为 32,768 tokens，输入与最大输出预算共用此容量；默认预留输出 8,192 tokens，因此不能把所有附件、历史与检索摘要无限累加。曾经出现的“模型接口拒绝工具参数”在长检索场景中实为上游上下文超限，被旧版统一的 HTTP 400 提示误分类。

现在两种语言的检索结果通过来源 ID 关联，同一组摘要只传一份。纯文本和文档请求使用团队服务 `/tokenize` 的实际分词结果检查容量，额外预留 512 tokens。包含当前或历史图片的请求使用保守估算，每图预留 6,144 tokens，避免下文所述多模态缓存问题。容量不足时依次缩短搜索摘要、移出早期完整问答、进一步缩短摘要，最后才调整输出预算；不直接截断当前问题、附件或工具消息 JSON。原始搜索结果与思考仍在前端工具记录、思考面板及导出中保留。若当前问题和必要资料仍无法容纳，会明确提示拆分。

其他模型服务或分词接口暂不可用时采用保守估算。若生成接口仍返回上下文超限，最多压缩并重试一次现有生成请求，不重新执行搜索。日志仅记录错误类别、状态码、轮数、检索次数与 token 预算，不记录原始错误正文、用户材料或密钥。认证、限流、工具协议、上下文容量与其他参数错误分别提示。

来源编号在一次提问内统一、按原链接去重。正文标注 `[S1]`、`[S2]`，或使用检索结果的原链接，才会进入“本次回答引用的来源”；未使用的结果保留在工具记录。下一次追问会将历史引用转成原链接，避免新旧编号混淆。

侧栏展示全部有效检索来源，“正文已引用”标记与“仅看已引用”筛选依据实际引用匹配结果。学术搜索取得的记录归入文献，其余归入网页；同一来源两种工具都取得时归入文献。编号保持原始引用编号，不按类别重新编号。来源不代表已阅读原文或逐条核验了论断。秘塔返回的是摘要；日期、作者等未提供时不猜测。搜索结果不足、失败或正文未标注可匹配引用时，页面会明确显示。

适配依据：[秘塔官方搜索 API 实验室](https://metaso.cn/search-api/playground)、[vLLM 原生工具调用说明](https://docs.vllm.ai/en/stable/features/tool_calling/)。

## 阅读与文件

- 采用紧凑桌面排版，正文默认 16 px，标题、思考、统计、提示文字改为近黑色。首页说明为“固废与资源循环领域的专家问答”。收起历史栏后正文最大宽度从 1,000 px 扩展至 1,180 px，输入框同步扩展；窄屏自动适配。
- 来源详情在桌面并排显示，窄屏变为带遮罩的抽屉；来源列表独立滚动，支持 Esc 关闭和键盘切换类别。正文引用保留紧凑数字标记，点击定位侧栏卡片。
- 对话和展开的思考共用一条滚动条。向上滚动、拖动滚动条或使用翻页键即暂停自动追随；点击“回到最新”恢复。生成中的界面更新合并到约每 80 ms，减轻长文本渲染负担。
- 支持 DOCX、PPTX、XLSX、XLS、PDF、TXT、Markdown、CSV、TSV、JSON，以及 PNG、JPG、WebP、GIF、BMP。旧版 DOC/PPT 请另存为 DOCX/PPTX。扫描 PDF 暂不做 OCR；可将所需页面作为图片上传。表格读取缓存值，公式不重新计算，内嵌图表和图片不自动抽取。
- 文档在独立进程内解析，最长 45 秒，保留至多 180,000 字符；模型每次每文档读取前 12,000 字符，每轮文档共用 24,000 字符，截取时向用户和模型明确提示。
- 图片会移除 EXIF 并压缩至最长边 2048 像素，以原生 `image_url` 内容块发送给所选模型；动图仅首帧。已实测团队与在线基线均能识别测试图。附件保留在所属用户消息里，追问可继续使用；上下文过长时连同较早完整问答一并移出并提示。
- 2026-10-06 图片空回答修复：对照实验中，新图片先经过团队 `/tokenize` 后，后续生成持续返回 HTTP 500（流式表现为 0 tokens）；相同像素、不同字节身份的图片直接生成成功。现绕过带图请求的 `/tokenize`，并在发送副本中加入固定 JPEG 注释建立新的缓存身份，像素、尺寸、本地预览和旧附件均保留。不是删除图片、改用 OCR 或切换到其他模型。此修复在客户端规避问题，服务端缓存的内部根因仍需其日志确认。
- 解析文本和处理后的图片存于本机 `runtime/uploads`，容量上限 500 MB。原始 Office/PDF 二进制不保留。浏览器只保存附件元数据；导出记录包含文件名和解析说明，不包含图片数据和密钥。
- 学术默认近十年优先：依据当前上海日期，查询词添加年份范围，并对返回的发表日期再筛选，排除明确超出范围的记录；无日期来源标为“年份未标明”。当前官方搜索 API 实验室未公开独立的十年过滤参数，因此没有假装调用未经确认的 API 参数。只有年份时按年份粒度处理，不把它视为精确到日的日期。

## 思考内容说明

2026-10-05 实测，两路模型均返回了独立的 `reasoning` 字段。思考开关是对上游模型的请求，实际是否返回仍取决于其服务配置。

展示的是模型接口提供的推理文本，不等同于对其内部计算的完整解释。思考内容与最终回答共享输出预算；若只收到思考、未完成回答，可增加最大输出 tokens，或关闭思考后重试。

适配依据：[vLLM reasoning outputs](https://docs.vllm.ai/en/latest/features/reasoning_outputs/)、[DMXAPI Qwen 思考参数](https://doc.dmxapi.cn/thinking-qwen.html)。

## 本机问答 API

`POST http://127.0.0.1:8910/api/chat`，JSON 请求，SSE 响应。本机调用无需再次传入模型密钥。

```json
{
  "provider": "team",
  "messages": [{"role": "user", "content": "如何制定疑似固废堆场的现场核查清单？"}],
  "thinking": true,
  "network_search": true,
  "temperature": 0.2,
  "max_tokens": 8192
}
```

`provider` 可为 `team` 或 `baseline`。`network_search` 默认 `false`，设为 `true` 才提供搜索工具。`system` 是可选系统提示词。多轮对话需在 `messages` 中交替传入完整的 `user` / `assistant` 消息，最后一条为 `user`。

每条事件为 `data: {JSON}\n\n`，`type` 取值：

- `start`：请求模型和思考开关。
- `reasoning`：本次新增的原始推理 `text`。
- `content`：本次新增的回答 `text`。
- `model_round`：模型进入下一轮工具选择或回答阶段。
- `tool_plan`：模型已返回原生工具调用；之前的本轮 `content` 是中间说明，客户端应清空当前答案缓冲，等待后续最终回答。
- `tool_start` / `tool_result`：调用 ID、工具名、查询词、返回来源、数量、用时或错误。停止生成会中止正在进行的模型或搜索连接。
- `citations`：从最终正文匹配的来源、未匹配引用编号及检索来源总数。
- `warning`：工具协议或输出提示；不会以普通文本触发替代搜索。
- `done`：实际模型、完成原因、`complete`、用量、耗时；`context_budgets` 记录各次请求的输入容量、输出预算、分词方式和容量调整。`complete: false` 表示回答未完整完成。
- `error`：错误 `message`。连接在收到 `done` / `error` 前结束时，应视为未完成。

`GET /api/health` 返回本机服务状态；`GET /api/providers` 返回不含密钥的模型配置状态；`GET /api/tools` 返回秘塔配置状态及两个可用工具名。

限制：单条消息最多 20,000 字、传入历史上下文合计最多 60,000 字、最多 41 条消息、每次模型生成输出 512–16,384 tokens；每模型最多两个并行请求。Agent 一次提问可能包含多次模型生成，显示的 token 用量为各次调用合计。模型空闲读取超时180秒、秘塔搜索超时50秒、单次提问总时限15分钟。停止按钮会中止本机上游连接，远端服务实际何时取消计算取决于其实现。

## 开发与验证

在上级 `wuyu-ai-platform` 目录构建前端：

```powershell
node .\node_modules\vite\bin\vite.js build --config .\model-chat\vite.config.mjs
```

在本目录运行检查：

```powershell
..\.venv\Scripts\python.exe -m unittest -v test_server.py test_agent.py test_attachments.py test_context_budget.py
```

`live_check.py` 会调用两路真实 API，产生实际推理用量；只在需要检查服务时手动运行。结果仅记录测试答案和推理字符数，不含密钥。
